# AirCanvas — рисование жестами перед камерой

Настольное приложение для бесконтактного рисования: кончик указательного пальца
управляет курсором, а сведение большого и указательного пальцев («щипок») рисует
линию. Работает локально на процессоре, без облачных сервисов и платных API.
Видео с камеры не записывается и никуда не отправляется.

**Гипотеза исследования:** «Отслеживание руки и сглаживание координат позволяют
реализовать бесконтактное рисование с помощью обычной веб-камеры.»

## Возможности

- Выбор веб-камеры и разрешения захвата (640×480, 960×540, 1280×720), кнопки «Включить камеру» / «Остановить».
- Отслеживание одной руки моделью MediaPipe Hand Landmarker (Tasks API, режим VIDEO).
- Зеркальный предпросмотр с ключевыми точками руки; направление курсора совпадает с зеркальным видом.
- Щипок с гистерезисом и нормализацией по размеру руки; настраиваемые пороги.
- Экспоненциальное сглаживание курсора с настраиваемым коэффициентом α.
- Холст 1280×720, масштабируется под окно с сохранением пропорций.
- 6 цветов, толщина кисти 2–40 px, «Отменить» (Ctrl+Z), «Очистить», «Сохранить PNG» (Ctrl+S).
- Резервный ввод мышью, когда камера выключена или недоступна (тот же движок штрихов).
- Строка состояния: камера, рука, рисование, фактическая частота обработки кадров.
- Панель «Диагностика»: частота обработки, среднее время работы модели, доля кадров с рукой,
  замеры неподвижной руки и экспорт агрегированных данных в CSV.
- Окно «О проекте» с описанием метода и ограничений.

## Установка

Нужен Python 3.11. Видеокарта не требуется.

### Windows (PowerShell)

```powershell
cd AirCanvas
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python download_model.py
python main.py
```

Если PowerShell запрещает запуск скрипта активации, выполните один раз
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` или используйте `cmd`:
`.venv\Scripts\activate.bat`.

Если по умолчанию установлен другой Python, укажите 3.11 явно: `py -3.11 -m venv .venv`.

### macOS / Linux

```bash
cd AirCanvas
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python download_model.py
python main.py
```

### Модель отслеживания руки

`download_model.py` один раз загружает файл `models/hand_landmarker.task` (~7,8 МБ)
из официального хранилища Google:

- Документация: <https://ai.google.dev/edge/mediapipe/solutions/vision/hand_landmarker>
- Файл: <https://storage.googleapis.com/mediapipe-models/hand_landmarker/hand_landmarker/float16/latest/hand_landmarker.task>

Скрипт выводит SHA-256 загруженного файла. Повторная загрузка: `python download_model.py --force`.
После загрузки приложение работает без интернета. Само приложение модель **не загружает**:
если файла нет, оно показывает инструкцию, а рисовать можно мышью.

### Разрешение на доступ к камере

- **Windows:** Параметры → Конфиденциальность и защита → Камера → включите «Доступ к камере»
  и «Разрешить классическим приложениям доступ к камере».
- **macOS:** Системные настройки → Конфиденциальность и безопасность → Камера → разрешите
  доступ приложению «Терминал» (или IDE, из которой запускается программа), затем перезапустите его.
- **Linux:** пользователь должен иметь доступ к `/dev/video*` (обычно группа `video`:
  `sudo usermod -aG video $USER`, затем перелогиниться).

Если камера занята другой программой (Zoom, Teams, браузер), приложение сообщит, что камера
недоступна или занята. Закройте другую программу или выберите другую камеру.

## Использование

1. Выберите камеру и нажмите «Включить камеру». Режим ввода переключится на «Жесты».
2. Поднимите руку ладонью к камере на расстоянии 40–80 см.
3. Перемещайте указательный палец — по холсту движется курсор (кольцо).
4. **Сведите большой и указательный пальцы, чтобы рисовать. Разведите их, чтобы остановиться.**
5. Выберите цвет и толщину кисти на панели инструментов. Если поменять их во время рисования,
   текущий штрих завершится и продолжится новым штрихом с новыми настройками.
6. «Отменить» удаляет последний штрих, «Очистить» — весь рисунок (с подтверждением).
7. «Сохранить PNG» сохраняет только холст 1280×720 на белом фоне — без предпросмотра камеры,
   курсора, ключевых точек и элементов интерфейса.

Когда камера выключена, рисовать можно мышью (режим «Мышь»). Пока работает камера, мышь
не рисует, чтобы два источника ввода не создавали конфликтующих штрихов.

## Как это работает

### Архитектура

| Файл | Назначение |
|---|---|
| `main.py` | Точка входа, создание `QApplication` |
| `window.py` | Интерфейс PySide6: холст, панель инструментов, предпросмотр, строка состояния, диалог «О проекте» |
| `camera_worker.py` | Захват кадров (отдельный поток хранит только последний кадр) и инференс в `QThread` |
| `hand_tracker.py` | Обёртка над MediaPipe Hand Landmarker (Tasks API, режим VIDEO) |
| `gestures.py` | Координаты, зеркалирование, сглаживание, щипок с гистерезисом, потеря отслеживания |
| `canvas.py` | Движок штрихов: структурированные штрихи, отрисовка, отмена, очистка, PNG |
| `diagnostics.py` | Скорость обработки, время модели, доля кадров с рукой, замеры, экспорт CSV |
| `download_model.py` | Однократная загрузка модели |

Захват и инференс выполняются вне GUI-потока. Интерфейс обновляется только в главном потоке
через сигналы Qt. Поток захвата постоянно читает камеру и хранит **только последний кадр**;
поток инференса берёт самый свежий кадр и ждёт, пока интерфейс обработает предыдущий
результат, поэтому очередь старых кадров не накапливается. Метки времени для
`detect_for_video` строго возрастают. При остановке и закрытии окна освобождаются камера,
модель и потоки.

### Система координат

MediaPipe возвращает координаты, нормированные к исходному кадру камеры. Они один раз
переводятся в «экранные» (зеркальные) координаты: `x_экр = 1 − x`, `y_экр = y`. Дальше
предпросмотр, курсор и холст используют только их. Внутренняя «активная зона» кадра
`[0,1; 0,9]` растягивается на весь холст, чтобы до краёв холста можно было дотянуться, не
выводя палец из кадра. Координаты ограничиваются границами холста.

### Щипок

`отношение = |кончик большого (4) − кончик указательного (8)| / |запястье (0) − основание среднего пальца (9)|`

Деление на размер руки делает признак независимым от расстояния до камеры. Если размер руки
близок к нулю (< 1e‑4), отношение не вычисляется и рисование прекращается.

Гистерезис: рисование начинается, когда отношение **меньше порога сведения** (по умолчанию 0,30),
и прекращается, когда оно **больше порога разведения** (0,45). Между порогами состояние
сохраняется, поэтому линия не прерывается от мелкого дрожания. Порог сведения обязан быть
меньше порога разведения — иначе приложение не применит новые значения. Текущее отношение
показывается на боковой панели, это помогает подобрать пороги под руку и камеру.

### Сглаживание

`s = α·x + (1 − α)·s_пред`, где `x` — новое положение курсора, `s` — сглаженное.

- α → 1: курсор следует за пальцем почти без задержки, но дрожит.
- α → 0: курсор устойчивый, но заметно запаздывает.
- Постоянная времени ≈ `−1 / ln(1 − α)` кадров (при α = 0,5 — около 1,4 кадра). Приложение
  показывает это значение рядом с настройкой.

По умолчанию α = 0,5. При потере руки сглаживание сбрасывается, поэтому курсор не «тянется»
из старого положения.

### Потеря отслеживания

Если рука не обнаружена, текущий штрих завершается, в строке состояния появляется
«Рука не обнаружена», и после повторного обнаружения начинается **новый** штрих — линия
между положениями до и после потери не рисуется. Если идентичность руки сомнительна
(сменилась «левая/правая» рука или запястье скачком переместилось больше чем на 25 % кадра
за один кадр), штрих также завершается.

### Штрихи и память

Штрих хранится как список точек, цвет и толщина. Линии рисуются со сглаживанием и
скруглёнными концами; неподвижный щипок даёт точку. Повторяющиеся точки не сохраняются.
Отмена перерисовывает сохранённые штрихи (снимки всего холста не хранятся). Ограничения
памяти: до 4000 точек в штрихе (длиннее — продолжается новым штрихом) и до 300 отменяемых
штрихов; более старые «впекаются» в фоновое изображение и отмене не подлежат.

## Диагностика

Кнопка «Диагностика» в заголовке открывает панель с измерениями:

- **Обработано кадров/с** — сколько кадров фактически прошло через модель за последние 2 с.
  Зависит от камеры, разрешения и компьютера; фиксированное значение не гарантируется.
- **Среднее время модели** — время только вызова `detect_for_video`. Это **не** полная задержка
  системы: не учитываются экспозиция и передача кадра камерой, преобразование изображения и вывод на экран.
- **Кадры с рукой** — доля обработанных кадров, в которых найдена рука.

«Экспорт CSV» сохраняет только агрегированные числа (настройки, итоги сеанса, результаты
замеров). Кадры видео не сохраняются.

## Воспроизводимый эксперимент (технические измерения)

Цель — сравнить устойчивость курсора и отзывчивость при разных коэффициентах сглаживания α.

1. **Условия.** Зафиксируйте и запишите: модель камеры, разрешение захвата, освещение
   (например, «верхний свет + окно сбоку»), фон, расстояние руки до камеры, компьютер (процессор, ОС).
   Камера неподвижна (штатив или край монитора).
2. **Подготовка.** Включите камеру, откройте «Диагностика». Поднимите руку, вытяните указательный
   палец, локоть упирается в стол.
3. **Замер неподвижной руки.** Установите α (например, 1,0 — без сглаживания), нажмите
   «Начать замер», держите руку неподвижно 15 секунд, нажмите «Завершить замер».
4. **Повторы.** Повторите для α = 1,0; 0,7; 0,5; 0,3; 0,15 — по 3 замера для каждого значения,
   в перемешанном порядке.
5. **Экспорт.** Нажмите «Экспорт CSV».

В каждой строке замера CSV:

| Поле | Смысл |
|---|---|
| `alpha` | коэффициент сглаживания |
| `frames`, `duration_s`, `fps` | число обработанных кадров, длительность, фактическая частота |
| `avg_inference_ms` | среднее время вызова модели |
| `detection_percent`, `tracking_losses` | доля кадров с рукой, число потерь отслеживания |
| `raw_std_x_norm`, `raw_std_y_norm` | стандартное отклонение **несглаженного** курсора, делённое на ширину/высоту холста |
| `smoothed_std_x_norm`, `smoothed_std_y_norm` | то же для **сглаженного** курсора |

Несглаженный и сглаженный курсор записываются в одном и том же замере, поэтому эффект
сглаживания можно сравнить без влияния различий между попытками.

6. **Отзывчивость.** Количественно её задаёт постоянная времени `−1/ln(1−α)` кадров;
   переведите её в миллисекунды, разделив на измеренный `fps`. Дополнительно опишите
   наблюдаемое: насколько курсор отстаёт при быстром движении пальца, «перелетает» ли
   он при остановке.
7. **Анализ.** Для каждого α посчитайте среднее и разброс `smoothed_std_*_norm` по повторам,
   постройте график «α — разброс» и «α — постоянная времени (мс)». Выберите компромисс.
8. **Отчёт.** Приведите условия, все замеры (включая неудачные), случаи потери руки и их
   вероятные причины (свет, перекрытие пальцев, край кадра, поворот ладони).

Результаты в этом репозитории **не приводятся**: их нужно получить на своём оборудовании.

## Тесты

```bash
python -m pytest -q
```

Автоматические тесты не требуют камеры и используют синтетические ключевые точки:
щипок и гистерезис, близкий к нулю размер руки, отображение и зеркалирование координат,
ограничение границами холста, сглаживание и его сброс, отсутствие соединяющей линии после
потери руки, точки при неподвижном щипке, отмена, очистка, смена кисти, размер и содержимое PNG.

Работу с настоящей камерой и жестами нужно проверять вручную.

## Ограничения

- Точность зависит от освещения, фона, перекрытия пальцев (например, ладонь ребром к камере),
  положения руки и её расстояния до камеры. Рука у края кадра отслеживается хуже.
- Отслеживается одна рука.
- Пороги щипка подобраны как разумные значения по умолчанию и могут потребовать настройки
  под конкретного человека и камеру.
- Скорость обработки зависит от компьютера, камеры и разрешения.
- Время модели — не полная задержка от движения до изображения на экране.
- Порядок камер в списке берётся из Qt и на некоторых системах может не совпадать с индексами
  OpenCV; если открылась не та камера, выберите другой пункт.
- Проверено только на Windows 11.
